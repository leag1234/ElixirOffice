# Fonts of the user's computer in the web editor ("Use my fonts")

State on 2026-10-07. Code: `web-apps/apps/common/main/lib/elixir-localfonts/` (branch `elixir/localfonts`),
HTTPS for the local network: `tools/lan-https/`, tests: `tests/localfonts/`.

## 1. In short

A Chromium browser (Chrome, Edge, Opera, Brave) can, with the user's consent, list and read the fonts installed
on the user's computer (*Local Font Access API*, `window.queryLocalFonts()`). The editor uses them: a teacher on a
Windows laptop that has Calibri, Cambria, Wingdings and her school fonts (Cursive standard, Belle Allure,
Écolier…) gets the exact page layout **without copying any font to the server**.

- Nothing is uploaded: the font bytes stay in the browser (no upload, no telemetry).
- Without consent nothing is read: the list of the computer's fonts is not even requested.
- When the API is not available (HTTP, Firefox, Safari), one line says why and what to do (Chrome or Edge over
  HTTPS, or the desktop app). Never an error.

## 2. What the user sees

1. When a document uses fonts the server does not have, a discreet bar (editing is not blocked) asks: "This
   document uses fonts that are not available on the server (Calibri, Cursive standard…). Use the fonts installed on
   this computer?" **[Use my fonts]** **[Not now]**. Fonts the server replaces by a clone with the same metrics
   (Arial, Times New Roman, Courier New) and the symbol fonts the engine always asks for (Symbol, Wingdings) do not
   trigger the bar by themselves; they are still taken from the computer once the user agreed.
2. A click on "Use my fonts" (the gesture the browser requires) brings up the browser's permission prompt. If it is
   granted: the consent is remembered (`localStorage`, per origin, key `elixir.localfonts.consent`), the fonts are
   registered in the editor, the document is laid out again (Word: in place; Excel and PowerPoint: a "Reload now"
   button), and a message lists the fonts applied and those that are not installed on the computer either.
3. On later openings: no bar; the computer's fonts are registered **before** the document fonts are loaded, so the
   very first layout is the right one.
4. **File > Options** (Advanced settings), group "Fonts": a switch "Use fonts installed on this computer" and its
   status (on: N fonts; refused; unavailable: HTTPS / browser). Switching it off withdraws the consent; the full
   effect is at the next opening.
5. Font list (ribbon): the computer's fonts are appended at the end of the list, drawn in their own font with the
   mark "On this computer".

Strings in 12 languages (en, fr, de, es, it, pt, pt-pt, nl, ru, pl, ja, zh) in `elixir-localfonts/Strings.js`.

## 3. Design

### Where the engine is hooked

The engine (sdkjs) measures and draws with the font files of its **runtime font index**: `AscFonts.g_font_files`
(one loader per file), `g_font_infos` (one `CFontInfo` per family: files and face numbers of the R/I/B/BI
styles), `g_map_font_index` (name -> family). This index is filled when `AllFonts.js` (generated by the server) is
loaded; the files are downloaded on demand by `CFontFileLoader`.

Chosen approach: **add entries to this index at run time**, with a lazy loader (`makeLoader` in `Core.js`):

- when the list is read (`queryLocalFonts()`, metadata only, a few hundred milliseconds), one family per family
  name of the computer is registered **if the server does not have that name** (the server wins on its own names:
  same font); variants addressed by their full name ("Calibri Light", "Segoe UI Semibold") are registered too;
- the file of a face is read (`FontData.blob()`) only when the document or the user needs it; its bytes are handed
  to the engine from memory (`CFontFileLoader.LoadFontFromData`), like a downloaded file;
- **selection rule** (same as `docs/fonts.md`): a real installed font under the **exact name** asked for beats the
  substitute (metric clone or similar font). Two thin wrappers on `g_fontApplication.GetFontFileWeb` /
  `GetFontFile` apply this rule for the computer's names; every other name follows the upstream path unchanged;
- a wrapper on `g_font_loader.LoadDocumentFonts` registers the computer's fonts **before** the document fonts are
  loaded when consent exists. It is installed by a *setter* on `AscCommon.g_font_loader`, because the page opens
  the document a few milliseconds after creating the engine: a timer-based installation arrived too late;
- face numbers: for a collection file (`.ttc`, e.g. Cambria + Cambria Math), the face number is found in the `name`
  table; for a variable font, the named instance (Bold, Light…) is requested from FreeType with
  `(instance + 1) << 16`; styles a family does not provide are produced by the engine (synthetic bold/italic), as
  for any incomplete font.

Alternatives rejected: the "fonts embedded in the document" path (`initEmbeddedFonts`) is meant for PDF and purges
its entries when reopened; writing into `AllFonts.js`/`font_selection.bin` would require changing the server
generator and redoing the substitute selection (`font_selection.bin` describes the server's fonts, not the
computer's).

### Layout again on the fly (Word)

After a consent given while a document is open, `LF.relayout` marks every paragraph for measuring again
(`Recalc_CompiledPr` + `Recalc_RunsCompiledPr`, as `OnEndLoadScript` does), clears the glyph caches and runs
`RecalculateFromStart`. The pages are laid out again without reloading. Excel and PowerPoint: "Reload now" button
(reloading the editor iframe reopens the document, with the fonts from the first layout).

### Permission and iframe

`apps/api/documents/api.js` adds `local-fonts` to the `allow` attribute of the editor iframe: a host application on
another origin (Nextcloud) must be able to delegate the permission; the browser remembers the permission for the
origin of the host page.

## 4. Limits

- **Chromium only** (Chrome, Edge 103+, Opera, Brave). Firefox and Safari do not implement the API: an explanation
  is shown. The desktop app already reads the system fonts (see `docs/fonts.md`).
- **HTTPS required** (or `localhost`): the API needs a secure context. For tests on the local network, see
  section 6.
- **PDF follows the computer, server-side conversions do not**: Download as PDF and Print create the PDF in the
  browser with the fonts of the screen, the computer's included (`docs/client-pdf.md`). Other server-side
  operations still use the server's fonts: conversions to other formats, thumbnails, PDF/A, and a PDF the server
  creates when the browser export falls back (the interface then says so).
- The displayed layout depends on the computer: two co-editors who do not have the same fonts see different
  pagination (as in Word). The document itself is not modified.
- Fonts the browser does not list: Office for Mac keeps Calibri/Cambria inside the application (`DFonts`), outside
  the system directories; `queryLocalFonts` cannot see them.
- Missing bold/italic: synthesized by the engine. Variable fonts: named instances only.
- No font of the computer is cached: each opening rereads those the document needs (a few tens of milliseconds to
  a few seconds for big CJK fonts).

### Next options (not done)

- **Client-side PDF / printing**: done for Word (`docs/client-pdf.md`); Excel and PowerPoint next.
- **Session-scoped font upload, with consent**: send the fonts in use to the server for the duration of the
  session and for this document only (licences: only with the user's explicit agreement and never kept), so that
  x2t and thumbnails use them too.
- Keep the bytes (IndexedDB) to speed up reopenings; warn when a document uses a font that neither the server nor
  the computer has.

## 5. Test fonts (never put fonts in git)

The tests use "Fira Sans" (SIL OFL), absent from the server pack, installed **on the test machine**:

```
mkdir -p ~/.local/share/fonts/elixir-localfonts-test
cd ~/.local/share/fonts/elixir-localfonts-test
for s in Regular Bold Italic BoldItalic; do
  curl -sLO https://github.com/google/fonts/raw/main/ofl/firasans/FiraSans-$s.ttf; done
fc-cache -f
```

The test browser then sees a real local font that the server does not have. The machine's Ubuntu Sans (variable
font) and Noto Sans CJK (`.ttc` collection) cover the variable and collection cases.

## 6. HTTPS for the local network (Caddy, internal authority)

`tools/lan-https/`: a separate Docker Compose project (`eo-lan-https`, `restart: unless-stopped`, only port 8443
published: Docker-published ports are not filtered by the host's ufw, so the LAN can reach it) serving
`https://$HOST:8443` (and `$HOST`, `localhost`) in front of the development instance `eo` (host port
8080), WebSocket included. It touches neither the demo (80/443) nor any other port. A browser sends no SNI for an IP
address, so the Caddyfile's `default_sni` is the LAN address (use that address, not the wifi one). The
certificate is issued by Caddy's internal authority ("Caddy Local Authority"); its root certificate can be
downloaded, without the key:

- `https://$HOST:8443/elixir-ca.crt` (root certificate, valid until 2036);
- `https://$HOST:8443/elixir-https.html` (one-page how-to for the tester, in French on purpose: it is
  end-user content for the French-speaking tester).

Deployment: `cp tools/lan-https/{docker-compose.yml,Caddyfile} $EO_WORK/lan-https/ && cp -r
tools/lan-https/static $EO_WORK/lan-https/ && cd $EO_WORK/lan-https && docker compose up -d`.
If the host's DHCP address changes, change it in the site address and in `default_sni` of the `Caddyfile` and restart.

### Trusting the certificate (once per computer)

**Windows 10 / 11** (Chrome and Edge use the Windows store):
1. download `elixir-ca.crt`; double-click, "Open";
2. "Install Certificate…", **Current User** (or "Local Machine" with administrator rights);
3. "Place all certificates in the following store", Browse, **Trusted Root Certification Authorities**; Next,
   Finish; answer **Yes** to the security warning;
4. close Chrome/Edge completely and reopen.

**macOS**: double-click `elixir-ca.crt` (Keychain Access, "login" keychain), double-click the certificate, "Trust" >
**Always Trust**, restart the browser.

**Remove**: `certmgr.msc` (Windows) or Keychain Access (macOS), delete "Caddy Local Authority". This certificate
is for this test server only; do not install it on a shared computer.

## 7. Verify

```
# test fonts installed (section 5), development instance with the feature on :8082
EO_BASE=http://localhost:8082 EO_INSECURE_BASE=http://$HOST:8082 \
EO_HTTPS_BASE=https://$HOST:8443 node tests/localfonts/run.mjs
```

`tests/localfonts/run.mjs` (Playwright, Chromium with the `local-fonts` permission, Firefox for the unsupported
case): the bar; nothing read before consent; after consent, line widths and line counts follow the local font, four
styles = four faces; variable font (real bold instance); collection (face number); font list (once, drawn);
File > Options; permission refused; reopening without a gesture (same layout, no bar); consent withdrawn; **no
request or WebSocket frame contains font bytes** and no request leaves the origin; fallback over HTTP on a
non-local address (HTTPS message); Firefox (browser message); Excel and PowerPoint; the HTTPS address is a secure
context with `queryLocalFonts`. Output: "0 failed checks".

By hand: open a `.docx` that uses a font installed on the computer but absent from the server, click "Use my
fonts"; `Common.ElixirLocalFonts.trace` (console of the editor iframe) gives the steps;
`Common.ElixirLocalFonts.status` is `on`.

Profile that trusts the authority: the test creates a separate NSS database (`certutil` from `libnss3-tools`,
variable `CERTUTIL`), installs `elixir-ca.crt` in it, starts Chromium with that `HOME` and opens the HTTPS address
**without a certificate exception**: valid chain issued by "Caddy Local Authority", `isSecureContext === true` and
`typeof queryLocalFonts === "function"`. The other cases use `ignoreHTTPSErrors` (no effect on whether the context
is secure). Command-line check of the chain:
`openssl s_client -connect $HOST:8443 -CAfile elixir-ca.crt -verify_ip $HOST` ("Verify return code: 0").
