## Prebuilt payload assembly without module execution

When nested Bubblewrap is unavailable, a prebuilt Electron payload can be assembled without executing build commands inside an app sandbox. Verify every source SHA in the filled manifest first. Initialize a new build directory with `flatpak build-init --arch=x86_64 --base=org.electronjs.Electron2.BaseApp --base-version=25.08 BUILD org.elixiroffice.desktop org.freedesktop.Sdk org.freedesktop.Platform 25.08`. Extract the checked Linux archive into `BUILD/files/lib/elixiroffice/` and install the four checked file sources at the exact destinations in the manifest, preserving the BaseApp files. Finish with the manifest command and all finish arguments. Run `tests/flatpak/metadata-equivalence.py MANIFEST BUILD/metadata`: it requires exact application/runtime/SDK/base/command and permissions, and verifies excess filesystem access is rejected.

`flatpak build-export --arch=x86_64 REPO BUILD beta` still invokes Bubblewrap for icon validation in Flatpak 1.14.10. Do not use `--disable-sandbox`, remove the icon or disable a validator. Stop if that sandbox is unavailable. With an explicitly approved export host, transfer only the assembled build to an owned release directory, verify all file hashes/modes/link targets, and run build-export followed by `flatpak build-bundle --arch=x86_64 REPO OUTPUT org.elixiroffice.desktop beta`. Keep XDG_DATA_HOME, XDG_CONFIG_HOME, XDG_CACHE_HOME, XDG_RUNTIME_DIR and FLATPAK_USER_DIR inside that owned directory. No installation, remote configuration or application execution is part of assembly.

The approved preview route uses Flatpak 1.14.10 for initialization/finish and 1.12.7 for export/bundle. Record that difference, the real export commit and all receipts. Initialize a fresh private repository with `ostree --repo=REPO init --mode=archive-z2`, then import the resulting bundle with build-import-bundle solely for static inspection; this is not an installation. Check the imported metadata and resource/licence hashes again. Final release inputs and native portal/printing/recovery/fonts/AI checks remain separate gates.

Desktop 0.2.1 candidates use application version 0.2.1-rc.N; the final uses 0.2.1 with a new build number, following the [shared build identity](../../docs/desktop-build-identity.md). The AppStream release entry must match the selected application version and date; the Flatpak manifest has no application-version property. Freeze the selected Linux payload only after tools/desktop/check-version.cjs verifies its app.asar version and bundled build identity. A separately approved export uses `ElixirOffice-<version>-x86_64.flatpak`, with the actual RC or final version. A final payload requires a rebuild and fresh acceptance; neither the frozen 0.2.0 package set nor the historical 0.1.0 preview certifies it. Flatpak export, installation and native gates remain separate from this identity preparation.
