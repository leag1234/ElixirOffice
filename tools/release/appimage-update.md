# External AppImage updates for desktop beta3

This is packaging preparation, not an application updater. AppImage naming is `ElixirOffice-0.2.0-x86_64.AppImage`; the `.deb`, Windows installer and macOS DMG names stay unchanged. The matching `ElixirOffice-0.2.0-x86_64.AppImage.zsync` is included in the final checksum/build-info inventory. Electron publish is explicitly null and build invocation uses never. No electron-updater dependency, updater API call or feed is added to the application. Public output rejects latest/beta/alpha update manifests.

`desktop-beta.sh` calls the new isolated repack driver for Linux after electron-builder. Selected product revisions must include the naming/publish config before --plan or build. Existing release work/output names still use the beta2 driver prefix; choose a distinct beta3 run label and owned remote root. No prior candidate is overwritten. Final notes template is desktop-beta3-release-notes.md and remains a review draft until final platform gates/checksums/source verification.

`appimage_update.py --prepare-only --cache OWNED_CACHE` verifies the exact tool manifest, obtains tools/licences inside a non-root isolated Docker builder and exercises only the tool version. It does not build an editor package. Default builder content ID is recorded in appimage-tools.json; `--appimage-builder-image` may only assert that exact reviewed content ID. A different builder needs a newly reviewed manifest/provenance receipt. No host packages or services are installed. Cache/work roots must be owned, marked and under the data work/cache directories, without symlink or parent traversal. A given tool cache is for one serialized release pipeline at a time.

Downloads and preparation use only pinned HTTPS inputs. Repacking runs network=none with two CPUs/four GiB/no swap/512PIDs, UID1000, drop-all capabilities/no-new-privileges, default Docker security profiles; source/pin mounts and prepared tools are read-only. It extracts the original AppDir and preserves its app/files, adds the pinned runtime licence and invokes pinned appimagetool with an explicit pinned runtime. Changed runtime/package bytes require fresh package/resource/privacy/native checks; no old AppImage checksum applies.

Default channel is latest-all, owner/lead approved for prereleases. Embedded update information is `gh-releases-zsync|leag1234|elixiroffice|latest-all|ElixirOffice-*x86_64.AppImage.zsync`. The final ELF update information, control Filename/URL/Length/SHA-1/table length and actual offline zsync rolling-block reconstruction are checked before publication inventory. Verification seeds all real final bytes and substitutes a closed loopback URL in a private control copy; missing blocks fail instead of being fetched. Only the original final-named `.zsync` is published. Both package/control SHA256s are in BUILD-INFO and SHA256SUMS. A native synthetic-data probe has also verified correct tables and rejected a corrupted table; that is not a packaged AppImage gate.

`tests/desktop/no-updates.test.cjs` checks runtime sources/dependencies/config and the real main bootstrap with throwing Electron updater, updater module and network APIs, plus deliberately injected failures. It starts no renderer/native Electron window, so packaged/native network smoke remains required. It distinguishes ordinary optional user-approved AI traffic from automatic updates. AppImageUpdate is a separate external utility: the user starts it and it contacts GitHub; ElixirOffice never checks for updates.

Mac rebuild remains Session A using the same frozen source/runtime/driver inputs locally, as beta2; D does not run builds on the owner Mac. Final Flatpak rebuild uses the same integrated inputs and its separate approved export-only route; owner installation and native portal/fonts/AI/recovery gates still require explicit permission. No final build, integration or publication is authorized by this document.

Desktop 0.2.0 uses the pre-release tag v0.2.0; the external update channel remains latest-all. The pipeline rejects already published version 0.1.0 before every target build and audits the packaged app.asar version. Fresh output folders default to desktop-0.2.0-DATE; legacy remote ownership markers remain unchanged. The Mac DMG must be rebuilt by session A from the reviewed version-bump commit, using the same final source/runtime pins.

## Launcher and sandbox

The repacker corrects generated AppImage desktop metadata to forward file URIs with `Exec=AppRun %U` and declare nineteen MIME types, including PDF. It preserves the upstream launcher environment. Supplied sandbox bypass flags are rejected. The launcher adds `--no-sandbox` only when `unshare -Ur true` fails (including a missing unshare command), and prints this warning to standard error:

> ElixirOffice: unprivileged user namespaces are unavailable, starting without the Chromium sandbox; use the .deb or the Flatpak for the sandboxed variant

This AppImage compatibility fallback is absent from the DEB and Flatpak launchers. Tests use a harmless argument-recording stub for both namespace outcomes and reject explicit bypass flags; they do not start an unsandboxed Electron process. Actual AppImage repacking and zero-fetch zsync verification are separate artifact gates.
