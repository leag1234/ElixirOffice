# OpenDocument round-trip gate (.odt / .ods / .odp)

Measure what a **Save** does to an OpenDocument file. The editor does not edit ODF natively: at open
the bundled converter (x2t, WebAssembly) turns the file into the editor's model, at save it turns the model back
into ODF. Anything the model or the converter does not carry is lost or simplified. The Word 74-document gate
does not see this; this gate does.

## Run it

```sh
export EO_XVFB=/path/to/Xvfb EO_PLAYWRIGHT=/path/to/node_modules/playwright EO_NODE=node   # on Linux
tools/fidelity/odf-roundtrip.sh --app /path/to/extracted-desktop-package [--out DIR] [--extra DIR]... [--jobs 4]
                                [--baseline previous/results.json] [--only '^w0']
```

* `--app` is an extracted package (an AppImage after `--appimage-extract`, `squashfs-root`) that contains the
  `elixiroffice` executable. Each document gets its own Xvfb display and profile; your own profile is never used.
* `--extra DIR` adds more `.odt/.ods/.odp` files, for example the Word gate corpus converted with LibreOffice
  (`soffice --convert-to odt`). Keep third-party documents outside git.
* `--baseline` compares with an earlier `results.json`: exit code 1 when a document fails, the package guard starts
  refusing, the page similarity drops by more than 0.03, or a feature goes from kept to changed/lost.
* The first run builds the LibreOffice tools image `eo-odf-lo:trixie` from `Dockerfile.odf-lo` (about 560 MB, Debian
  trixie, LibreOffice 25.2). A 115-document run takes about 6 minutes with 3 jobs.

## What it does

1. `odf_corpus.py` writes 41 flat ODF documents (19 Writer, 12 Calc, 10 Impress), one feature group each, so a loss
   can be attributed. Every document is generated by the script; nothing is third party. LibreOffice normalises them to
   real `.odt/.ods/.odp` (`odf_postprocess.py` sets the frozen panes, which flat ODF cannot carry).
2. `odf-roundtrip-app.cjs` opens each file in the packaged app, types one character away from the features and deletes
   it, runs the real save conversion and captures the bytes the app writes. It also records whether the package guard
   (`desktop/package-guard.cjs`) would refuse the in-place save (embedded objects lost) and keeps the editor
   output (`editor-output.doct|xlst|pptt`) so the converter can be replayed alone.
3. `odf_render_compare.py` renders original and round trip with LibreOffice (PDF), compares the page count, the page
   similarity (ink density on a 10 mm grid, 1.0 = identical) and the text overlap (words per document, layout
   independent).
4. `odf_struct.py` diffs the XML by feature (styles, lists, tables, images, frames, fields, comments, tracked changes,
   objects, charts, formulas, number formats, masters, notes, animations...). `odf_report.py` aggregates it into the
   loss table: per feature how many documents kept, changed or lost it, with examples.

Outputs in the run directory: `loss-table.md`, `results.json`, `documents.csv`, `render/render.json`, per-document
`work/<id>/roundtrip.json` and the round-tripped file in `rt/`.

## Reading the result

* **kept**: the count or set of items is the same after the round trip.
* **changed**: present on both sides but different (a number, a style set, a level).
* **lost**: present before, absent after.
* *Generic differences* lists what every LibreOffice-authored file shows (renamed automatic styles, default styles
  added by the converter). They are informational and do not count against a baseline.
* *Corpus gaps* means a synthetic document lost its intended feature during LibreOffice normalisation; fix the
  generator, the app is not at fault.
* The page similarity is a coarse indicator: below 0.5 look at the page, around 0.8 is what a one-line shift gives.

## Replaying only the converter

The captured editor output can be converted again with another x2t build, without the editor, which is how a core
fix is checked in a minute: `node docx-roundtrip-x2t.mjs X2T_JS work/<id>/editor-output.doct out.odt 8193 67`
(`xlst` 8194 to ods 259, `pptt` 8195 to odp 131). Reader fixes (ODF to editor) need the app, because they change what
the editor receives; install the runtime in a copy of the package with `tools/wasm/install-runtime.py`.

Unit tests: `python3 tests/fidelity/odf-corpus.test.py`; converter regressions (need an x2t build):
`EO_X2T_JS=... EO_NODE=... python3 tests/fidelity/odf-x2t-fixes.test.py` and
`python3 tests/fidelity/odf-comments-sections.test.py` (comments, page style switches, text sections with columns).
